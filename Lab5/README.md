# Лабораторна робота №5: клієнтська частина (Front-end) та інтеграція з API

Односторінковий застосунок (SPA) для інформаційно-аналітичної системи підрозділу кіберполіції.
Працює із захищеним REST API з лабораторних №3 і №4.

```
Lab5/
  backend/    API (NestJS + PostgreSQL) з ЛР3-ЛР4 + налаштований CORS і довідники міст/кваліфікацій
  frontend/   SPA: React 18 + TypeScript + Vite + Tailwind CSS + Axios + React Router
```

## Швидкий запуск (3 кроки, 2 термінали)

Потрібні: Node.js 20+ та Docker.

**1. База даних і API** (перший термінал):

```bash
cd backend
cp .env.example .env            # CORS_ORIGIN=http://localhost:5173 уже заданий
docker compose up -d            # PostgreSQL (порт 5433) зі схемою й тестовими даними
npm install
npm run start:dev               # API: http://localhost:3000/api/v1, Swagger: http://localhost:3000/api/docs
```

> Якщо ще працює контейнер із попередньої лабораторної, спочатку `docker compose down` у тій папці
> (порт 5433 і ім’я контейнера збігаються).

**2. Фронтенд** (другий термінал):

```bash
cd frontend
npm install
npm run dev                     # SPA: http://localhost:5173
```

Відкрийте http://localhost:5173. Обліковий запис адміністратора: `admin` / `Admin2027Pass`
(створюється при запуску API з `backend/.env`). Звичайного оператора створіть через форму реєстрації.

## Що реалізовано

| Вимога | Реалізація |
|---|---|
| Структура проєкту | `components`, `pages`, `services/api`, `store`, `routes`, `hooks`, `utils`, `types` |
| HTTP-клієнт | один екземпляр axios (`services/api/httpClient.ts`), сервіси `AuthService`, `PersonsService`, ...; прямих викликів HTTP у компонентах немає |
| Interceptor | додає `Authorization: Bearer`; на 401 один раз оновлює токен через `/auth/refresh` і повторює запит, інакше розлогінює |
| Реєстрація / вхід | форми з валідацією (логін від 3 символів, пароль від 8 із літерою та цифрою), токени в `localStorage` |
| Protected Routes | `PrivateRoute` (перенаправлення на `/login`), `RoleRoute` (адмін-панель лише для admin) |
| Шапка | ім’я користувача, роль, кнопка «Вихід» |
| CRUD | таблиця, деталі, створення, редагування (поля заповнені), видалення з підтвердженням |
| UX | спінери, сповіщення (toasts), повідомлення валідації, обробка помилок із кнопкою «Спробувати ще раз» |
| CORS | на сервері: дозволено лише адреси з `CORS_ORIGIN` |
| **Бонус** | пагінація на клієнті разом із пошуком і фільтрами (параметри `page`, `limit` API) |

Оператор бачить сторінки й форми, але кнопка «Видалити» та адмін-панель доступні лише адміністратору
(сервер додатково повертає 403).

## Тести

```bash
cd frontend && npm test            # 26 тестів: валідація, interceptor, захищені маршрути, форма входу, пагінація
cd frontend && npm run test:live   # 8 інтеграційних перевірок проти запущеного API (створює тестові записи)
cd backend  && npm test            # 20 тестів API
```

## Сценарій демонстрації (відео 30–60 с)

Реєстрація → вхід → створення запису → перегляд → видалення (як admin) → вихід.
